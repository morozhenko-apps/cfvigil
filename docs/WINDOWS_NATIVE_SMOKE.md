# Windows desktop verification

Verify the checksum of the Windows installer before executing it. Do not bypass SmartScreen or disable antivirus globally to force installation.

On a real Windows desktop, verify installation and Start menu identity, tray icon, compact and expanded card, Settings and Event History, keyboard focus, search, notifications and correct resizing on varying display scaling. In the expanded card, an unconfigured account and zero resources must produce a short content-height window, not a tall empty list; one, many and filtered resources must grow/shrink the window while retaining the bottom anchor. Right-click on the card, Settings, About and History must never display WebView2's Back, Refresh, Save as, Print or Share menus. The app's own resource action button must still work. The frameless About window must be draggable from its upper empty strip, including under display scaling, without stealing Close or link clicks.

After applying Cloudflare credentials, check that the card immediately shows a pending-sync indicator before the first response. It must not temporarily claim Cloudflare is disconnected, nor claim success before verified data arrives. Inspect a Pages project with a newer Preview and an older successful Production deployment: Production determines the card. Check Worker deployments separately without assuming the production branch is literally named main.

Open Settings with a new and an existing account. The Apply button must become usable after loading the native configuration; a temporary/failed read must show an error rather than leave an unexplained disabled button and must retry on reopening Settings. Exercise account, token replacement, interval, locale and autostart independently and verify saved values after reopening. A slow save must present visible progress without accidentally submitting twice. Capture only redacted screenshots; never expose account identifiers or tokens.

Confirm that language and token changes happen only when Apply is used, that Cancel does not persist drafts and that native credential storage never exposes the token to the WebView. Check autostart enable/disable, relaunch, account switching and brief offline recovery.

Test an upgrade, ordinary uninstall, and uninstall with **Delete the application data** checked. Upgrade and ordinary uninstall must preserve the app's credential. Explicit full-data removal must erase CFVigil's own generic entry from Windows Credential Manager in addition to app-specific Roaming/Local user data. Check for the credential by target name before and after; never print its secret value. Confirm that reinstall does not inherit an old token. Test an already-absent credential and failure to delete a locked/inaccessible entry: a failure must be visible rather than falsely reported as complete erasure. This must be observed on a real Windows installation.

Record reproducible defects as issues with sanitized screenshots and steps. Release-check details belong in CI logs, not this document.
